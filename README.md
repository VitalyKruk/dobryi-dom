# Добрый дом 🐾

Веб-сервис приюта для кошек и собак: каталог, карточки питомцев, многошаговая заявка, личный кабинет и кабинет сотрудника.
Собран по [PROMPT.md](PROMPT.md) — улучшенной версии исходного промпта для Lovable.

## Продукт

Требования к продукту описаны в [PRD «Добрый дом»](https://claude.ai/code/artifact/1d344de4-b216-4e37-9eed-7454fe37054f). Главное из него:

- **Цель — 60 дней от приюта до дома.** Это главная метрика; остальные метрики дашборда `/admin` показывают, где путь затягивается: время решения по заявке, доля одобрений, заявки без ответа дольше 3 дней, «забытые» питомцы, спрос на функции в разработке.
- **Роли:** гость, пользователь, волонтёр и администратор. Карточки питомцев ведёт администратор, администраторов двое.
- **Открытые вопросы:**
  - где хостим продакшн и на каком домене;
  - какой платёжный сервис подключаем для донатов;
  - по какому числу переходов по фейкдорам решаем подключать оплату и заводить соцсети.

## Запуск

```bash
npm install
npm run dev
```

`npm run dev` поднимает сразу два процесса: API (`server/`, порт 3001, перезапускается при правках) и Vite (http://127.0.0.1:5173), который пересылает `/api` и `/uploads` в API. Данные API — в папке `data/` (`db.json` и загруженные фото), при первом запуске она заполняется демо-данными.

- `npm run build` — сборка фронтенда с проверкой типов (включая сервер);
- `npm run test:api` — интеграционные тесты API;
- `npm run server` — только API.

## Бэкенд

REST API на Node 24 + Express 5 в [server/](server/). TypeScript запускается напрямую (Node сам снимает типы), без сборки.

- **Хранилище** — JSON-файл `db.json` ([server/store.ts](server/store.ts)). Запись атомарная (временный файл + переименование) и последовательная, так что параллельные запросы не портят файл.
- **Вход** — пароли хешируются scrypt с солью, вход выдаёт токен сессии (`Authorization: Bearer …`). В базе лежит только хеш токена.
- **Права** проверяются на сервере по той же матрице ролей, что в интерфейсе ([server/auth.ts](server/auth.ts)). Пользователь видит и отзывает только свои заявки, внутренние заметки о питомцах получает только персонал.
- **Валидация** — zod-схемы ([server/schemas.ts](server/schemas.ts)). Ошибка — `400` с текстом по каждому полю; формы показывают их под полями.
- **Загрузка фото** — `POST /api/uploads`, тело — сам файл (JPG/PNG/WebP, до 5 МБ). Тип проверяется по сигнатуре файла, а не по заголовку; имя файла придумывает сервер.

### Ограничения частоты и адрес посетителя

Счётчики живут в памяти API ([server/rate-limit.ts](server/rate-limit.ts)) и обнуляются при его перезапуске. Лишний запрос получает `429` с понятным текстом и заголовком `Retry-After` (сколько секунд ждать).

| Адрес                     | Лимит                                                                                            |
| ------------------------- | ------------------------------------------------------------------------------------------------ |
| `POST /api/auth/login`    | 5 неудачных входов на один email за 15 минут (с любых адресов) и 20 с одного IP (на любые email) |
| `POST /api/client-errors` | 20 в минуту с одного IP                                                                          |
| `POST /api/fake-doors`    | 30 в минуту с одного IP                                                                          |

- **Вход.** Неудачная попытка, исчерпавшая лимит, и все следующие до конца окна получают «Слишком много неудачных попыток входа. Попробуйте снова через N мин.». Пока блокировка действует, пароль не проверяется — даже верный. Незарегистрированные email считаются так же, иначе по `429` было бы видно, есть ли такой аккаунт. Успешный вход обнуляет счётчик своего email, но не IP: иначе свой аккаунт сбрасывал бы лимит между попытками подбора.
- **Журнал.** Блокировка записывается один раз за окно: в журнал действий — «Вход заблокирован» с причиной (по email или по IP), замаскированным email и IP; в лог API — событие `login_locked`. Первый лишний запрос к ошибкам и фейкдорам — событие `rate_limited` с IP и путём.
- **Обратная сторона.** Зная email сотрудника, можно на 15 минут закрыть ему вход серией неверных паролей. Если это станет проблемой — капча или вход по ссылке из письма.

**Адрес посетителя** (`req.ip`) API берёт из `X-Forwarded-For`, доверяя стольким прокси, сколько указано в переменной `TRUST_PROXY`:

| Где                                                        | Цепочка             | `TRUST_PROXY`          |
| ---------------------------------------------------------- | ------------------- | ---------------------- |
| `npm run dev`                                              | Vite → API          | не задана (`loopback`) |
| Docker, [compose.yaml](compose.yaml)                       | nginx → API         | `1`                    |
| Прод, [deploy/compose.prod.yaml](deploy/compose.prod.yaml) | Caddy → nginx → API | `2`                    |

Каждый прокси дописывает в конец `X-Forwarded-For` адрес, от которого получил запрос. API берёт N-й адрес с конца — тот, что записал ближайший к посетителю прокси. Всё, что левее, мог прислать сам посетитель, и это не учитывается, так что подделать адрес заголовком нельзя.

- **Почему число, а не подсети Docker.** В локальном стеке посетитель приходит к nginx через шлюз Docker, а он в той же частной подсети, что и прокси. Доверие к подсети позволило бы такому посетителю подставить свой адрес.
- **Подсети тоже можно**: адреса и подсети через запятую, как в настройке `trust proxy` Express (`loopback, 10.0.0.0/8`). `true` API не принимает — с ним адрес подделывался бы одним заголовком.
- **Если цепочка изменится** (например, перед Caddy встанет CDN), число нужно поменять, иначе лимиты будут считаться по адресу прокси.

### Postgres

Прод-стек хранит данные и загруженные фото в Postgres — сервис `db` в [compose.yaml](compose.yaml) (образ `postgres:17.11-alpine`, том `db-data`). Перед первым запуском скопируйте `.env.example` в `.env` и задайте `POSTGRES_PASSWORD`.

```bash
docker compose up -d --build web api
```

- **Схема** — [server/schema.sql](server/schema.sql). API применяет её при каждом запуске (`create table if not exists`), отдельных миграций нет. Каждая запись лежит целиком в колонке `data` (jsonb), поля для поиска и сортировки вынесены в колонки.
- **Фото** — в таблице `uploads` (bytea, до 5 МБ). API отдаёт их по адресу `/uploads/<имя>`.
- **Запись.** После каждого изменения в базу одной транзакцией уходит только разница: новые и изменённые строки, удаление исчезнувших.
- **Доступ.** Порт базы открыт только на этом компьютере: `127.0.0.1:5433` (меняется через `DB_PORT`).
- **Перенос данных.** При первом запуске на пустой базе данные и фото переносятся из тома `api-data` (`db.json` и `uploads/`).
- **Тесты.** `npm run db:start` поднимает базу, `npm run test:postgres` прогоняет тесты API на Postgres в отдельной базе `dobryi_dom_test` (`TEST_DATABASE_URL` в `.env`, создаётся сама). Тесты сбрасывают в ней данные к демо, поэтому имя базы обязано оканчиваться на `_test` — до рабочей базы они не доберутся.
- **Ограничения.** Один процесс API на базу. Dev-контейнер и `npm run dev` без `DATABASE_URL` работают на JSON.

### Логирование

**Логи API** ([server/logger.ts](server/logger.ts)) пишутся в stdout по одной JSON-строке на событие. Смотреть их:

```bash
docker compose logs -f api
```

- **Каждый запрос**: метод, путь, статус, время ответа, роль и id пользователя, id запроса. Тот же id приходит клиенту в заголовке `X-Request-Id`. При ошибке 500 он есть и в ответе — по нему находится запись в логе.
- **Ошибки 5xx** записываются со стеком. Ошибки 4xx пишутся с уровнем `warn`, проверка здоровья — `debug`.
- **Уровень** задаёт переменная `LOG_LEVEL`: `debug`, `info` (по умолчанию), `warn`, `error` или `silent`. В тестах — `silent`.
- **Чего в логах нет:** тел запросов, query-строк (там бывает поиск по имени), email, паролей и токенов. IP посетителя пишется только в события защиты — `login_locked` и `rate_limited` (см. «Ограничения частоты»), email там замаскирован.

**Ошибки фронтенда** ([src/lib/report-error.ts](src/lib/report-error.ts)). Необработанные ошибки и сбои отрисовки страниц отправляются на `POST /api/client-errors` и попадают в тот же лог с уровнем `warn` и сообщением `client_error`.

- Отправляются тип, текст, стек и путь страницы без параметров.
- Не больше 10 сообщений за загрузку страницы, повторы отбрасываются.
- При сбое страницы посетитель видит экран «Страница сломалась» с кнопкой обновления.

**Журнал действий** (`/admin/audit`, только администратору) показывает, кто и когда:

- подал, одобрил, отклонил или отозвал заявку и оставил комментарий;
- добавил, изменил или удалил питомца и сменил его статус;
- сменил роль пользователя, расписание волонтёров или сбросил данные;
- вошёл в систему или ввёл неверный пароль (email в такой записи замаскирован);
- исчерпал лимит неудачных входов — запись «Вход заблокирован» с IP.

Журнал хранится в базе, последние 2000 записей. Демо-данные приходят со стартовой историей.

**Действия Claude Code.** Хук в [.claude/settings.json](.claude/settings.json) после каждой команды и правки файла дописывает строку в `logs/claude-actions.log`.

- В строке: время, начало id сессии, инструмент и команда или путь к файлу.
- Токены и пароли в командах заменяются на `***`.
- Папка `logs/` не попадает в git.

Промпты пишет отдельный хук ([scripts/log-prompt.mjs](scripts/log-prompt.mjs)) — в [PROMPTS.txt](PROMPTS.txt). Файл лежит в git, поэтому секреты (токены, ключи, пароли, пароли в адресах подключения) в нём заменяются на `***`, а служебные сообщения приложения (`<task-notification>` и подобные) не записываются. Маскировку делает общий [scripts/redact.mjs](scripts/redact.mjs) — тот же, что у журнала действий.

### Версия без сервера

```bash
npm run build:static
```

Результат — `dist-static/artifact.html` (одна страница: JS, стили и шрифты внутри) и папка `dist-static/photos/`. `dist-static/index.html` — то же самое в обычной HTML-обёртке, для локального просмотра.

Чем эта версия отличается:

- **API работает в браузере** ([src/lib/api-static.ts](src/lib/api-static.ts)). Он использует те же схемы валидации, права, аналитику и подбор, что и сервер.
- **Данные** хранятся в `localStorage` у каждого зрителя. «Сбросить демо-данные» возвращает их к исходным.
- **Внешние ресурсы не используются.** Фото питомцев скачиваются один раз в `.static-cache/` и кладутся рядом со страницей. Карта заменена ссылкой на OpenStreetMap.
- **Маршруты** хранятся в памяти, адресная строка не меняется.

В обычной сборке и в Docker всё по-прежнему работает через настоящий сервер.

### Docker

Продакшн: nginx раздаёт сайт и пересылает `/api` и `/uploads` в контейнер API; данные API лежат в томе `api-data`. Адрес — http://localhost:8081 (другой порт — `WEB_PORT=9000 docker compose up web`):

```bash
docker compose up --build web api
```

Разработка с hot reload в контейнере (Vite и API вместе) — http://localhost:5173:

```bash
docker compose --profile dev up dev
```

nginx настроен под SPA: прямые ссылки вида `/pet/persik` и `/admin/pets` открываются без 404. Файлы из `/assets/` кешируются на год (в их именах есть хеш), `index.html` — без кеша. Проверка здоровья — `GET /healthz`.

**Прод** (https://dobryi-dom-s-hvostikamy.ru) — тот же compose плюс [deploy/compose.prod.yaml](deploy/compose.prod.yaml): Caddy с HTTPS от Let's Encrypt перед nginx, порты web и db закрыты. Регламент сборки и выкатки — проверки до и после, откат, особые случаи и известные ловушки — [deploy/README.md](deploy/README.md).

### Линтеры

```bash
npm run lint          # проверить
npm run lint:fix      # исправить, что можно, автоматически
```

Скрипт [scripts/lint.mjs](scripts/lint.mjs) запускает пять проверок:

1. **oxlint** — ошибки в TS/React-коде ([.oxlintrc.json](.oxlintrc.json)).
2. **Prettier** — единое форматирование ([.prettierrc.json](.prettierrc.json)). Демо-данные, файлы shadcn и исходное ТЗ исключены в [.prettierignore](.prettierignore).
3. **knip** — неиспользуемые файлы, экспорты и npm-зависимости ([knip.json](knip.json)). Компоненты shadcn в `src/components/ui` не проверяются — это библиотека.
4. **hadolint** — Dockerfile.
5. **actionlint** — workflow GitHub Actions, вместе с ShellCheck для команд в `run`.

hadolint и actionlint работают в Docker, ставить их не нужно; без запущенного Docker они пропускаются с предупреждением. При ошибках код выхода 1. `npm run lint -- --if-changed` пропускает проверку, если с последней успешной ничего не менялось.

**Автозапуск:**

- **Перед коммитом** — git-хук [.githooks/pre-commit](.githooks/pre-commit). Включается сам при `npm install` (скрипт `prepare` задаёт `git config core.hooksPath .githooks`). Пропустить разово: `git commit --no-verify`.
- **В Claude Code** — Stop-хук запускает [scripts/lint-hook.mjs](scripts/lint-hook.mjs) после каждого хода, в котором менялись файлы. При ошибках Claude получает отчёт и исправляет их, прежде чем закончить ход.
- **В CI** — `npm run lint` на каждый push и pull request.

### Проверка на уязвимости

```bash
npm run security
```

Скрипт [scripts/security-scan.mjs](scripts/security-scan.mjs) запускает:

1. **npm audit** — известные уязвимости в npm-зависимостях.
2. **Trivy fs** — уязвимости в `package-lock.json`, утёкшие секреты (ключи, токены) и ошибки в Dockerfile/compose.
3. **Trivy image** — пакеты в образах сайта и API (перед этим образы пересобираются).

Считаются находки уровня HIGH и CRITICAL; при них код выхода 1. Trivy работает в Docker, ставить его не нужно. Отчёты складываются в `.security/`.

- `npm run security:quick` — без сборки и сканирования образа.
- `npm run security -- --if-changed` — пропустить, если с последней успешной проверки ничего не менялось.

Trivy не проверяет на секреты файлы с `test` в пути — это его встроенное правило для тестовых фикстур.

**Автозапуск в Claude Code:** Stop-хук из [.claude/settings.json](.claude/settings.json) после каждого хода, в котором менялись файлы, запускает [scripts/security-hook.mjs](scripts/security-hook.mjs). При находках Claude получает отчёт и исправляет проблему, прежде чем закончить ход.

### CI: GitHub Actions

Workflow [.github/workflows/docker.yml](.github/workflows/docker.yml) запускается на push в `main`, на теги `v*` и на pull request:

1. **Линтеры, сборка и тесты** — `npm ci`, `npm run lint` (все пять линтеров), `npm run build` (с проверкой типов), `npm run test:api` и `npm run test:postgres`.
2. **Образы Docker** — сборка сайта и API и smoke-тест всего стека через compose: прямые ссылки SPA, кеш ассетов, API через nginx (валидация, права, сохранение заявки в Postgres).
3. **Публикация** (кроме PR) — в GitHub Container Registry: `ghcr.io/vitalykruk/dobryi-dom` (сайт) и `ghcr.io/vitalykruk/dobryi-dom-api` (API) с тегами `latest` (main), `sha-…`, имя ветки, версии из тега `v1.2.3`.

Действия GitHub Actions закреплены по хешу коммита, образ Postgres — по точной версии: подменённый тег не попадёт в сборку. Обновления раз в неделю предлагает Dependabot ([.github/dependabot.yml](.github/dependabot.yml)) pull request'ами.

## Сценарий и состояния

Основной сценарий — подбор питомца и заявка:

1. **Вход** — главная `/`: счётчики, «Питомцы недели», переход в каталог.
2. **Работа с данными** — каталог `/catalog` (фильтры, поиск, сортировка, пагинация) → карточка `/pet/:id` (галерея, избранное).
3. **Ввод** — заявка `/apply/:petId`: 4 шага с валидацией, черновиком и сводкой.
4. **Результат** — экран «Ура! Заявка отправлена» с номером заявки → статус в кабинете `/account`.

Каждый экран с данными умеет четыре состояния: загрузка (скелетоны той же формы), данные, пусто и ошибка с кнопкой «Попробовать ещё раз». Для показа есть демо-режим — параметр в адресе, действует до закрытия вкладки. Клиент передаёт его серверу заголовком `X-Demo`, и ошибка приходит настоящим HTTP 503:

| Ссылка                | Что показывает                                                                |
| --------------------- | ----------------------------------------------------------------------------- |
| `/catalog?demo=slow`  | ответы идут ~2.5 с — видны скелетоны                                          |
| `/catalog?demo=error` | сервер «не отвечает» — экраны ошибок; при отправке форм — сообщение об ошибке |
| `/catalog?demo=empty` | пустые списки — пустые состояния                                              |
| `?demo=off`           | обычная работа                                                                |

Пока режим включён, в левом нижнем углу видна плашка с его названием и кнопкой «Выключить».

## Данные и как выводится результат

**Данные приближены к реальным.**

- **33 питомца** с настоящими фото, кадрированными по мордочке. У каждого 21 поле: порода, вес, прививки, совместимость с детьми и животными, характер, история, уход.
- **85 заявок за 14 недель.** Поток растёт, по выходным заявок больше.
- **Правдоподобные решения по заявкам.**
  - У каждого пристроенного питомца есть одобренная заявка за несколько дней до отъезда домой.
  - Пристроенные питомцы проводили в приюте 55–64 дня, в среднем 60 — ровно цель из PRD.
  - Отказы согласованы с анкетой: у кандидата кошка, а питомец с кошками не ладит; маленькие дети и питомец, который их боится; большая собака и маленькая квартира.
  - На рассмотрении — только свежие заявки.
- **Генератор истории** ([src/lib/seed-history.ts](src/lib/seed-history.ts)) детерминированный: при каждом сбросе получается та же картина, сдвинутая к сегодняшней дате.

**Формы вывода результата:**

| Форма        | Где                                                                                                                                                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Дашборд      | `/admin`. Подсказки «Что сделать на этой неделе», KPI с трендом, заявки по неделям по статусам, воронка «подано → рассмотрено → одобрено → дома», спрос на кошек и собак, причины отказов, самые популярные питомцы |
| Таблицы      | Админка: заявки (поиск, вкладки по статусам, страницы), питомцы, волонтёры, расписание дежурств, пользователи и роли                                                                                                |
| Карточки     | Каталог, «Мои заявки», отзывы                                                                                                                                                                                       |
| Рекомендации | «Подходят вам» — `/match` и вкладка в кабинете: процент совпадения и причины («Ладит с детьми», «Удобно в квартире»); «Кому ещё у вас будет хорошо» после отправки заявки; «Похожие питомцы»; «Питомцы недели»      |
| Теги         | Причины совпадения, характер, статусы, «Новенький», совместимость                                                                                                                                                   |
| Summary      | Сводка анкеты перед отправкой, экран «Заявка отправлена» с номером, факты о питомце                                                                                                                                 |

Подбор ([src/lib/match.ts](src/lib/match.ts)) работает так:

- Питомцев, которые точно не подойдут, отсекает: не ладит с детьми, а в семье малыши; не ладит с кошками, а дома кошка.
- Остальных ранжирует по жилью, опыту и характеру, а также по виду и размеру из избранного.
- Тех, на кого у человека уже есть заявка или кто лежит в избранном, не предлагает.

## Что стоит знать

- **Жёлтый акцент** (`Button variant="default"`) — только для главного действия экрана. Остальные кнопки: `secondary`, `outline`, `ghost`.
- **Контраст**: все пары текст/фон проходят WCAG AA. Поэтому текст на голубом — `#3E5F85`, а не `#5B7FA6` из исходного ТЗ, а статусы — светлая заливка с тёмным текстом.
- **Фото** — с Unsplash (проверены вручную: кошки — кошки, собаки — собаки). Если фото не загрузится, появится заглушка с лапкой.
- **Фейкдоры.** Кнопка оплаты доната и кнопки соцсетей (VK, Telegram, YouTube) ведут на страницу `/soon/:feature` «Данный раздел находится в разработке» (после доната — «Спасибо, что решили помочь нашим друзьям-хвостикам», после соцсетей — «Спасибо, что заинтересовались нашими хвостиками», у YouTube ещё «…и вы сможете посмотреть на их жизнь в нашем приюте»). Каждый переход засчитывается; администраторы видят счётчики на дашборде в панели «Кнопки в разработке» — так видно, на что есть спрос, до того как подключать оплату и заводить соцсети ([src/lib/fake-door.ts](src/lib/fake-door.ts)).
- **Хранилище** — один JSON-файл: для приюта с сотнями записей этого хватает. При росте нагрузки его стоит заменить на SQLite или Postgres — меняется только `server/store.ts`.
- **Ограничения прототипа:** нет подтверждения email и восстановления пароля (форма «Забыли пароль?» — заглушка), лимиты частоты живут в памяти одного процесса API, нет рассылки писем (настройки уведомлений есть). Продакшн-хостинг, домен и платёжный сервис ещё не выбраны — см. открытые вопросы в разделе «Продукт».
