# Добрый дом 🐾

Веб-сервис приюта для кошек и собак: каталог, карточки питомцев, многошаговая заявка, личный кабинет и кабинет сотрудника.
Собран по [PROMPT.md](PROMPT.md) — улучшенной версии исходного промпта для Lovable.

## Запуск

```bash
npm install
npm run dev
```

`npm run dev` поднимает сразу два процесса: API (`server/`, порт 3001, перезапускается при правках) и Vite (http://127.0.0.1:5173), который пересылает `/api` и `/uploads` в API. Данные API — в папке `data/` (`db.json` и загруженные фото), при первом запуске она заполняется демо-данными.

- `npm run build` — сборка фронтенда с проверкой типов (включая сервер);
- `npm run test:api` — интеграционные тесты API;
- `npm run server` — только API.

## Бэкенд

REST API на Node 24 + Express 5 в [server/](server/). TypeScript запускается напрямую (Node сам снимает типы), без сборки.

- **Хранилище** — JSON-файл `db.json` ([server/store.ts](server/store.ts)). Запись атомарная (временный файл + переименование) и последовательная, так что параллельные запросы не портят файл.
- **Вход** — пароли хешируются scrypt с солью, вход выдаёт токен сессии (`Authorization: Bearer …`). В базе лежит только хеш токена.
- **Права** проверяются на сервере по той же матрице ролей, что в интерфейсе ([server/auth.ts](server/auth.ts)). Пользователь видит и отзывает только свои заявки, внутренние заметки о питомцах получает только персонал.
- **Валидация** — zod-схемы ([server/schemas.ts](server/schemas.ts)). Ошибка — `400` с текстом по каждому полю; формы показывают их под полями.
- **Загрузка фото** — `POST /api/uploads`, тело — сам файл (JPG/PNG/WebP, до 5 МБ). Тип проверяется по сигнатуре файла, а не по заголовку; имя файла придумывает сервер.

| Метод и адрес | Что делает | Доступ |
|---|---|---|
| `GET /api/pets` | каталог: фильтры, поиск, сортировка, страницы | все |
| `GET /api/pets/:id`, `/similar`, `/featured`, `/count` | карточка, похожие, «питомцы недели», счётчик | все |
| `POST /api/applications` | заявка на знакомство (повтор на того же питомца — `409`) | все |
| `GET /api/applications` | свои заявки / все для персонала | вошедшие |
| `POST /api/applications/:id/cancel` | отозвать свою заявку | вошедшие |
| `PATCH /api/applications/:id/status` | сменить статус (одобрение бронирует питомца) | админ |
| `POST /api/applications/:id/comments` | комментарий сотрудника | персонал |
| `POST /api/auth/login`, `/register`, `/logout` | вход, регистрация, выход | все |
| `GET`/`PATCH /api/me`, `PUT /api/me/favorites` | профиль и избранное | вошедшие |
| `POST`/`PUT`/`DELETE /api/pets…`, `POST /api/uploads` | карточки питомцев и фото | админ |
| `PATCH /api/pets/:id/status` | статус питомца | персонал |
| `GET /api/users`, `PATCH /api/users/:id/role`, `/api/volunteers` | роли и волонтёры | админ |
| `POST /api/volunteer-requests`, `/subscribe`, `/feedback` | анкеты и подписка | все |
| `GET /api/stats`, `/api/health` | статистика, проверка здоровья | все |

### Docker

Продакшн: nginx раздаёт сайт и пересылает `/api` и `/uploads` в контейнер API; данные API лежат в томе `api-data`. Адрес — http://localhost:8081 (другой порт — `WEB_PORT=9000 docker compose up web`):

```bash
docker compose up --build web api
```

Разработка с hot reload в контейнере (Vite и API вместе) — http://localhost:5173:

```bash
docker compose --profile dev up dev
```

nginx настроен под SPA: прямые ссылки вида `/pet/persik` и `/admin/pets` открываются без 404. Файлы из `/assets/` кешируются на год (в их именах есть хеш), `index.html` — без кеша. Проверка здоровья — `GET /healthz`.

### Проверка на уязвимости

```bash
npm run security
```

Скрипт [scripts/security-scan.mjs](scripts/security-scan.mjs) запускает:

1. **npm audit** — известные уязвимости в npm-зависимостях.
2. **Trivy fs** — уязвимости в `package-lock.json`, утёкшие секреты (ключи, токены) и ошибки в Dockerfile/compose.
3. **Trivy image** — пакеты в образах сайта и API (перед этим образы пересобираются).

Считаются находки уровня HIGH и CRITICAL; при них код выхода 1. Trivy работает в Docker, ставить его не нужно. Отчёты складываются в `.security/`.

- `npm run security:quick` — без сборки и сканирования образа.
- `npm run security -- --if-changed` — пропустить, если с последней успешной проверки ничего не менялось.

Trivy не проверяет на секреты файлы с `test` в пути — это его встроенное правило для тестовых фикстур.

**Автозапуск в Claude Code:** Stop-хук из [.claude/settings.json](.claude/settings.json) после каждого хода, в котором менялись файлы, запускает [scripts/security-hook.mjs](scripts/security-hook.mjs). При находках Claude получает отчёт и исправляет проблему, прежде чем закончить ход.

### CI: GitHub Actions

Workflow [.github/workflows/docker.yml](.github/workflows/docker.yml) запускается на push в `main`, на теги `v*` и на pull request:

1. **Линтер, сборка и тесты** — `npm ci`, `npm run lint`, `npm run build` (с проверкой типов), `npm run test:api`.
2. **Образы Docker** — сборка сайта и API и smoke-тест всего стека через compose: прямые ссылки SPA, кеш ассетов, API через nginx (валидация, права, сохранение заявки в `db.json`).
3. **Публикация** (кроме PR) — в GitHub Container Registry: `ghcr.io/vitalykruk/dobryi-dom` (сайт) и `ghcr.io/vitalykruk/dobryi-dom-api` (API) с тегами `latest` (main), `sha-…`, имя ветки, версии из тега `v1.2.3`.

## Сценарий и состояния

Основной сценарий — подбор питомца и заявка:

1. **Вход** — главная `/`: счётчики, «Питомцы недели», переход в каталог.
2. **Работа с данными** — каталог `/catalog` (фильтры, поиск, сортировка, пагинация) → карточка `/pet/:id` (галерея, избранное).
3. **Ввод** — заявка `/apply/:petId`: 4 шага с валидацией, черновиком и сводкой.
4. **Результат** — экран «Ура! Заявка отправлена» с номером заявки → статус в кабинете `/account`.

Каждый экран с данными умеет четыре состояния: загрузка (скелетоны той же формы), данные, пусто и ошибка с кнопкой «Попробовать ещё раз». Для показа есть демо-режим — параметр в адресе, действует до закрытия вкладки. Клиент передаёт его серверу заголовком `X-Demo`, и ошибка приходит настоящим HTTP 503:

| Ссылка | Что показывает |
|---|---|
| `/catalog?demo=slow` | ответы идут ~2.5 с — видны скелетоны |
| `/catalog?demo=error` | сервер «не отвечает» — экраны ошибок; при отправке форм — сообщение об ошибке |
| `/catalog?demo=empty` | пустые списки — пустые состояния |
| `?demo=off` | обычная работа |

Пока режим включён, в левом нижнем углу видна плашка с его названием и кнопкой «Выключить».

Фронтенд: Vite, React 19, TypeScript, Tailwind CSS 4, shadcn/ui (Radix), React Router 7, react-hook-form, zod 4, Sonner, lucide-react.

## Что стоит знать

- **Жёлтый акцент** (`Button variant="default"`) — только для главного действия экрана. Остальные кнопки: `secondary`, `outline`, `ghost`.
- **Контраст**: все пары текст/фон проходят WCAG AA. Поэтому текст на голубом — `#3E5F85`, а не `#5B7FA6` из исходного ТЗ, а статусы — светлая заливка с тёмным текстом.
- **Фото** — с Unsplash (проверены вручную: кошки — кошки, собаки — собаки). Если фото не загрузится, появится заглушка с лапкой.
- **Оплата доната** — заглушка: открывается окно «Здесь будет платёжный виджет».
- **Хранилище** — один JSON-файл: для приюта с сотнями записей этого хватает. При росте нагрузки его стоит заменить на SQLite или Postgres — меняется только `server/store.ts`.
- **Ограничения прототипа:** нет подтверждения email и восстановления пароля (форма «Забыли пароль?» — заглушка), нет ограничения частоты попыток входа.
